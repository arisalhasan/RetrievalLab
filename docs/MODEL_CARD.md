# RetrievalLab model and data card

**Purpose:** compare scientific-evidence retrieval methods on the official BEIR SciFact corpus. Intended for education, reproducible experimentation, and a local portfolio demonstration. Not a medical advice system, scientific fact checker, or production clinical service.

**Data:** official BEIR SciFact, 5,183 indexed documents. Official train has 809 claims; the frozen seed-42 grouped development split uses 647 for training and 162 for validation. Official test is evaluated only after release freeze. Queries, titles, abstracts, and official relevance labels are used without synthetic benchmark labels. The official archive, upstream source, checksum, and dataset terms are documented in the existing data guide and download manifest. Do not imply ownership or relicense upstream data/weights when distributing this project's code.

**Post-test split audit:** among the 300 official test queries, **157** share at least one positive evidence document with the 647 claims used for fine-tuning, and **61** have a training claim with token-set Jaccard similarity at least 0.8. These properties were measured only after the release freeze and official test access; neither weights nor settings changed in response. The official benchmark split is preserved. This is not proof that test labels entered training, but it limits claims about unseen-evidence or independent-topic generalization. The train-derived validation split separately prevents shared positive evidence between its training and validation partitions. Exact IDs and the lexical threshold are in `releases/v1/post-test-data-audit.json`.

**Systems:** local BM25; pinned all-MiniLM-L6-v2 normalized embeddings with FAISS exact inner-product search; reciprocal rank fusion of lexical/dense ranks; pinned two-layer MS MARCO TinyBERT cross-encoder; an explicitly versioned SciFact fine-tuning experiment. Checkpoint/configuration hashes, upstream revisions, and package versions are in manifests. Source code is available locally; Git commit identity is null in this mirrored workspace, so file hashes supply the available provenance. No Git-hosted repository, public deployment, or external code review is claimed.

**Training:** a small two-epoch CPU experiment, all known positives and one BM25 plus one random assumed negative per training query, seed 42, AdamW and binary cross entropy. Epoch 0 is eligible in checkpoint selection. Validation selects a checkpoint; official test never updates weights or chooses hyperparameters. The pretrained parent may have seen related public scientific material during pretraining; its original training data cannot be audited here. This project prevents local split leakage but cannot prove absence of upstream contamination.

**Limitations:** SciFact is small and domain-specific; no general web-search or out-of-domain claim follows. Relevance judgments are incomplete. Negatives may contain unlabeled relevant evidence. Shared-evidence/lexical grouping cannot eliminate semantic overlap. Repeated validation exploration can overfit selection. Neural token limits truncate many long abstracts. A reranker cannot recover evidence outside its candidate input. Cosine similarity, BM25 scores, RRF scores, and raw logits have different scales; none is a truth probability or calibrated confidence. Relevant documents can support or refute a scientific claim.

**Performance:** actual validation and held-out evidence is in the versioned result reports. Preserve regressions and failed improvement hypotheses. Paired bootstrap intervals and sample counts accompany point estimates. Latency includes fresh inference but excludes preparation/HTTP/UI; first API calls include initialization in caller-observed response time. Memory is whole-process sampled RSS. Tests and experiments used a Windows CPU workstation; GPU execution, other operating systems, fresh-machine installation, public hosting, internet-facing security, high concurrency, and million-document scale were not executed or established.

**Operation:** local-only assets, no paid APIs, no telemetry pipeline, one serialized CPU API request at a time, meaningful 422/429/503 errors. Changed data/config/model assets require explicit preparation and a new experiment identity. There is no monitoring of real users, scheduled retraining, or automatic test-based promotion.
